# TypedDoc Server-Generated PDF Fix Plan

## Objective

The project must download a real server-generated formatted PDF instead of silently falling back to a browser printout.

There are two separate requirements:

1. Generate the PDF on the server with the TypedDoc renderer.
2. Preserve the original document layout and formatting as closely as possible.

The current project can achieve the first with `server/services/pdfExportService.js`. The second requires coordinate-aware OCR output and a faithful page renderer.

## 1. Remove browser-print fallback from formatted downloads

In:

```text
src/components/FileUpload.jsx
```

The current logic is similar to:

```js
if (job.formattedPdf) {
  downloadBase64File(
    job.formattedPdf,
    `${job.file.name.replace(/\\.[^/.]+$/, '')}.pdf`,
    'application/pdf'
  );
} else {
  exportToPdf(
    job.file.name.replace(/\\.[^/.]+$/, ''),
    job.content
  );
}
```

Replace it with:

```js
if (!job.formattedPdf) {
  toast.error(
    'Server-formatted PDF was not generated. Please retry the conversion.'
  );
  return;
}

downloadBase64File(
  job.formattedPdf,
  `${job.file.name.replace(/\\.[^/.]+$/, '')}_formatted.pdf`,
  'application/pdf'
);
```

Remove the `exportToPdf` import from `FileUpload.jsx` if it is no longer used there.

This guarantees that the **Download Formatted PDF** button only downloads a PDF generated by the server.

## 2. Keep browser printing as a separate feature

The function in:

```text
src/services/export.js
```

that contains:

```js
window.print();
```

is a browser-print generator. It may be kept only for an explicitly labelled action such as:

```text
Print current view
```

It must not be used for:

```text
Download formatted PDF
```

Use separate buttons:

- **Download Server PDF** — downloads `formattedPdf` from the backend.
- **Print Current View** — optional browser print action.

## 3. Replace the editor PDF export path

The editor currently uses browser printing:

```text
src/components/Editor.jsx
```

Current pattern:

```js
} else if (format === 'pdf') {
  setShowPrintPreview(true);
  setMode('preview');
  await new Promise(r => setTimeout(r, 800));
  await exportToPdf(title, content, { pageMode: pdfPageMode });
}
```

For the real formatted PDF, create a backend endpoint such as:

```text
POST /api/v1/render/pdf
```

Request:

```json
{
  "title": "DMS Module 5",
  "content": "...markdown content...",
  "pageMode": "clean-reflow"
}
```

The backend should call:

```js
const pdfBuffer = await createPdfBuffer(title, content, {
  pageMode: 'clean-reflow',
  compactTypography: true
});
```

Then return the PDF as a binary response, signed URL, or base64 response for smaller files.

The editor should download the server response instead of calling `window.print()`.

## 4. Do not create a PDF during client-side OCR fallback

In:

```text
src/services/chunkedOcr.js
```

The client-side OCR fallback currently returns:

```js
{
  text: clientResult.text,
  formattedPdf: null,
  formattedDocx: null,
  clientSide: true
}
```

That is correct. The UI must not then call `exportToPdf()` automatically.

Instead, show:

```text
OCR completed in browser mode. Server-formatted PDF is unavailable. Please retry when the server is available.
```

The client-side fallback should provide text only and should not imply that it has the same PDF quality as the server renderer.

## 5. Add renderer metadata to generated PDFs

Inside:

```text
server/services/pdfExportService.js
```

inside `createPdfBuffer()`, add:

```js
pdfDoc.setTitle(title || 'TypedDoc Document');
pdfDoc.setAuthor('TypedDoc');
pdfDoc.setCreator('TypedDoc Server PDF Engine');
pdfDoc.setProducer('TypedDoc PDF Renderer');
pdfDoc.setSubject('AI-transcribed formatted document');
pdfDoc.setCreationDate(new Date());
```

A server-generated PDF should identify itself as:

```text
Creator: TypedDoc Server PDF Engine
Producer: TypedDoc PDF Renderer
```

A browser-generated PDF commonly identifies itself as:

```text
Creator: Chrome
Creator: Microsoft Edge
Creator: Mozilla/5.0...
```

## 6. Return PDF source information from the API

The backend should return metadata such as:

```js
{
  formattedPdf,
  pdfSource: 'server-pdf',
  renderer: 'pdf-lib',
  pageMode: 'clean-reflow',
  pageCount: pdfBuffer.pageCount,
  sourcePageCount: totalPages,
  expansionRatio: pdfBuffer.expansionRatio
}
```

For client OCR fallback:

```js
{
  formattedPdf: null,
  pdfSource: 'unavailable',
  clientSide: true
}
```

The UI can then clearly display:

```text
Server-rendered PDF
```

or:

```text
Server PDF unavailable
```

## 7. Understand the difference between server PDF and original layout

The current `pdfExportService.js` creates a real server-side PDF, but it currently produces a clean reflowed document.

It cannot reproduce the exact original layout from Markdown alone because Markdown does not contain:

- original x/y positions;
- handwriting coordinates;
- diagram coordinates;
- table geometry;
- whitespace relationships;
- source-region boundaries;
- relative positions of equations and annotations.

Therefore:

```js
createPdfBuffer(title, markdown)
```

creates a real PDF, but not an exact visual replacement of the original scanned document.

## 8. Implement faithful original-layout mode

The OCR output must return coordinate-aware structured blocks:

```json
{
  "page": 1,
  "pageWidth": 2480,
  "pageHeight": 3508,
  "blocks": [
    {
      "type": "heading",
      "text": "Module 5",
      "bbox": [160, 180, 1900, 280],
      "confidence": 0.98
    },
    {
      "type": "paragraph",
      "text": "Document management systems...",
      "bbox": [180, 340, 2200, 520],
      "confidence": 0.95
    },
    {
      "type": "math",
      "latex": "A = B \\cup C",
      "bbox": [220, 600, 1500, 760],
      "confidence": 0.91
    }
  ]
}
```

The faithful renderer should:

1. Create one output page for each source page.
2. Preserve the original page dimensions.
3. Place typed blocks at their original coordinates.
4. Preserve diagram crops when confidence is low.
5. Render equations at their original positions.
6. Add selectable text over the typed layout.
7. Report unresolved or low-confidence areas.

For a 27-page source, faithful mode should normally produce close to 27 pages.

## 9. Provide two PDF modes

### Clean reflow PDF

- Server-generated.
- Compact academic formatting.
- May have more pages than the original.
- Good for reading and editing.
- Does not preserve exact source positions.

### Faithful original-layout PDF

- Server-generated.
- Same page dimensions and approximately the same page count.
- Uses OCR bounding boxes.
- Preserves source layout.
- Best for converting handwritten notes into typed notes without changing structure.

## 10. Add strict automated tests

Test PDF metadata:

```js
test('PDF is generated by TypedDoc server renderer', async () => {
  const pdfBuffer = await createPdfBuffer(
    'Test Document',
    '# Heading\\n\\nThis is a test.'
  );

  const pdfDoc = await PDFDocument.load(pdfBuffer);

  assert.strictEqual(
    pdfDoc.getCreator(),
    'TypedDoc Server PDF Engine'
  );

  assert.strictEqual(
    pdfDoc.getProducer(),
    'TypedDoc PDF Renderer'
  );
});
```

Also test that:

- the formatted-download button never calls `window.print()`;
- server PDF generation returns a non-empty PDF;
- no browser metadata appears in server-generated output;
- page count is recorded;
- page mode is recorded;
- source page count and expansion ratio are recorded;
- client OCR fallback disables formatted PDF download.

```text

```

## Final architecture

### Server-generated formatted PDF

```text
OCR
  -> structured AST
  -> server pdfExportService
  -> formattedPdf
  -> direct download
```

### Optional browser print

```text
Editor preview
  -> explicitly labelled Print Current View
  -> window.print()
```

These must remain separate features.

## Final checklist

- Remove `exportToPdf()` fallback from `FileUpload.jsx`.
- Do not generate a PDF automatically from client-side OCR.
- Change editor PDF export to call the backend renderer.
- Keep `window.print()` only as an explicitly labelled print feature.
- Add PDF metadata identifying the TypedDoc renderer.
- Return `pdfSource`, `renderer`, `pageMode`, and `pageCount`.
- Add automated metadata and page-count tests.
- Change OCR output from Markdown-only to coordinate-based structured JSON for exact layout preservation.
- Implement separate `clean-reflow` and `faithful` PDF modes.

## Key conclusion

A server-generated PDF and an original-layout PDF are not the same thing.

The new `pdfExportService` can generate a real PDF without browser printing. To preserve the original layout, OCR must retain page coordinates, block types, source regions, and confidence metadata throughout the pipeline.
